# 합성 물품 100개 분실자 흐름 테스트

2026년 11월 19일에 분실자 검색부터 사진 확인과 수령 OTP 발급까지 검증했다. 실제 Gemini와 로컬 FastAPI API를 사용했다. 질문, 선택지, 응답, 후보 변화와 모델별 HTTP 상태는 [실행 기록 JSON](ownership_claimant_100_20261119.json)에 있다.

## 테스트 데이터

임시 SQLite DB에 합성 물품 100개를 직접 입력했다. 일반 물품 25개, 특징이 비슷한 물품 25개, 일부 특징이 빈 물품 40개, 보관 전이거나 보관 배정이 종료된 물품 10개다. 이 중 보관 중인 90개를 검색에 사용했다. 물품에는 종류, 색상, 형태, 표면 질감, 구조, 브랜드, 문구, 구별 특징과 습득 위치를 섞어 저장했다. 사진 응답 확인에는 테스트용 JPEG를 사용했다.

각 물품의 특징, 습득 위치와 보관 상태는 [합성 물품 100개 데이터](ownership_claimant_corpus_100_20261119.json)에서 확인할 수 있다.

검색 API에 자연어를 보낸 뒤 각 질문에 시나리오에 맞는 선택지를 제출했다. 사진 단계에서는 JPEG 응답을 읽고 ‘맞아요’ 또는 ‘아니에요’를 보냈다. 발급 여부는 API 응답과 DB에 새로 생긴 OTP 레코드 수를 함께 확인했다. 모델 한 번의 요청에 15초 타임아웃을 적용했다.

## 완료한 사례

| 입력과 시나리오 | 실제 답변 및 후보 변화 | 결과 | 첫 API 응답 |
| --- | --- | --- | --- |
| `파란 물병을 잃어버렸어요.` | 형태 5지선다에서 `원통형` 선택. 후보 5개에서 `T01` 하나로 좁힘 | 사진 ‘맞아요’, OTP 1건 | 33.6초 |
| `검은색 우산을 잃어버렸어요.` | 재질 5지선다에서 `nylon` 선택. 후보 5개에서 `U01` 하나로 좁힘 | 사진 ‘맞아요’, OTP 1건 | 12.8초 |
| `흰색 Apple 이어폰을 잃어버렸어요.` | `M01`의 브랜드가 비어 있어 종류와 색상으로 찾음. 확인할 질문이 소진된 상태에서 사진 단계로 이동 | 사진 ‘맞아요’, OTP 1건 | 7.9초 |
| `보온병을 찾고 있어요.` | 자동 추출 특징만 있는 `M03` 한 개를 찾음. 남은 질문 없이 사진 단계로 이동 | 사진 ‘맞아요’, OTP 1건 | 9.5초 |
| `보온병을 찾고 있어요.` | `M03` JPEG를 받은 뒤 ‘아니에요’ 선택 | `photo_rejected`, OTP 0건 | 26.2초 |
| `수첩을 잃어버렸어요.` | 장식에 `열쇠고리`, 문구에 `AZ` 선택. `N01`은 첫 오답 뒤 남았고 두 번째 독립 오답 뒤 제외됨 | `wrong_evidence_limit`, OTP 0건 | 43.1초 |
| `잃어버린 지갑이 있는지 찾아주세요.` | `은색 나뭇잎`과 `AB` 선택. 후보 5개에서 동일한 답이 맞는 `W01`, `W02` 두 개가 남음 | `multiple_candidates`, OTP 0건 | 18.5초 |
| `잘 모르겠어요.` | 비교할 단서가 추출되지 않아 추가 입력 안내 | `needs_clues`, OTP 0건 | 1.8초 |

물병의 실제 형태 보기는 `원통형`, `직육면체`였고, Gemini가 만든 보기는 `피라미드형`, `원추형`, `구형`이었다. `원통형`을 제출한 뒤에는 `T01` 사진을 확인하고 OTP를 발급받았다.

## API 오류로 완료하지 못한 사례

| 시나리오 | 실제 실행 결과 |
| --- | --- |
| 도서관 1층 필통의 질문 5개에 모두 정답 | 첫 실행은 첫 질문의 보기 생성에서 요청 제한이 발생했다. 순차 재실행은 후보 비교에서 Gemini 서비스 오류가 발생했다. |
| 수첩의 독립 근거 1개 오답 | 순차 재실행에서 첫 질문을 불러와 `하트 배지`를 제출했다. 다음 질문의 보기 생성에서 Gemini 서비스 오류가 발생했다. |
| 보관 대상인 헬멧이 없음 | 한 실행은 후보 비교에서 API 오류가 발생했다. 순차 재실행은 단서 추출 중 마지막 모델 `gemini-2.5-flash-lite`가 HTTP 404를 반환했다. |

11개 시나리오 중 8개가 기대 결과와 일치했고 3개는 모델 호출에서 중단됐다. 전체 91회 요청 중 HTTP 200은 31회, 429는 33회, 503은 18회, 404는 1회였으며 HTTP 응답을 받지 못한 요청은 8회였다. 최초 병렬 실행에서 요청 제한이 발생해 영향받은 사례를 순차 재실행했다. 응답 시간에는 당시 API 상태와 대체 모델 호출 시간이 포함된다.

같은 로컬 코드에서 백엔드 자동 테스트는 133개 통과했고 PostgreSQL 전용 3개는 건너뛰었다. 자동 테스트에서는 비공개 근거 1개 오답 허용, 다섯 질문 진행, 후보 없음 분기를 확인했다.

## 재현

`backend` 디렉터리에서 아래처럼 실행하면 같은 100개 데이터가 임시 DB에 생성된다. 여러 사례를 검증할 때는 `--case` 값과 출력 경로를 바꿔 순차 실행한다.

~~~powershell
$env:GEMINI_TIMEOUT_SECONDS = '15'
$runPath = Join-Path $env:TEMP ('ownership-claimant-' + [guid]::NewGuid().ToString('N'))
python -m app.ai_ownership_verification.experiments.run_ownership_live --output-dir $runPath --suite user-flows --case bottle_shape_match
~~~
