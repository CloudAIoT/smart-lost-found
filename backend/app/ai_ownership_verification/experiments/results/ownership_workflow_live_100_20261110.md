# 합성 물품 100개로 소유 확인 흐름 검증

2026-11-10에 별도 SQLite DB에 합성 물품 100개를 등록하고, 실제 Gemini(`gemini-3.5-flash-lite`)를 연결해 검색 입력부터 내부 판정 결과 조회까지 확인했다. 일반 물품 25개, 비슷한 물품 25개, 특징이 일부 비어 있는 물품 40개, 검색 대상에서 제외된 물품 10개로 구성했다. 검색 대상은 90개였다. 확인 질문에 사용할 비공개 특징과 시나리오별 응답은 미리 정의했다.

## 실제 Gemini와 함께 실행한 결과

12개 사례를 준비했고 10개를 시도했다. 기대 결과 일치 5개, 상태 불일치 1개, API 오류로 미완료 4개, 미실행 2개였다. API 요청 17회 중 13회는 처리됐고, 17번째 요청의 `429` 사용량 제한에서 실행을 중단했다.

| 입력 또는 상황 | 실제 결과 |
| --- | --- |
| 도서관 근처에서 잃어버린 필통 | 후보 5개에서 1개로 좁힌 뒤 다섯 번째 질문까지 진행했다. 비공개 근거 5개가 일치했고 내부 결과에서 `P01`, `supported`, 답변 수 5개를 확인했다. |
| 지갑 질문에 두 번 모두 ‘모르겠어요’ 선택 | `insufficient_evidence`로 종료됐다. |
| 등록되지 않은 보라색 바이올린 | `no_candidates`가 반환됐다. |
| ‘잘 모르겠어요’만 입력 | `needs_clues`가 반환됐다. |
| 확인할 비공개 근거가 없는 보온병 | 질문 없이 `insufficient_evidence`가 반환됐다. |
| ‘애플’만 입력 | Gemini가 브랜드를 포함한 모든 단서에 `null`을 반환해 `needs_clues`가 나왔다. 실험에서 예상한 상태는 `no_candidates`였다. |
| 브랜드가 비어 있는 이어폰에 ‘애플’ 입력 | 단서 추출 요청이 실패해 DB 검색까지 진행하지 못했다. |
| 등록 특징과 불일치하는 답변 | 수첩을 찾는 단서는 추출했지만 선택지 생성 요청이 실패했다. |
| 공개 특징만으로 후보를 좁히는 경우 | 단서 추출 요청이 실패했다. |
| 브랜드 키 자체가 없는 빨간 책갈피 | 단서 추출 요청에서 `429`가 발생했다. |
| 보관 조건 불충족과 후보 과다 | 사용량 제한 이후 두 사례는 미실행했다. |

필통 사례의 첫 질문 선택지는 서버에서 구성했고 이후 네 질문의 선택지는 Gemini로 생성했다. 사진 선택과 선재 백엔드 연동은 이 실행 범위 밖이다. `supported`는 현재 개발용 정책에서 소유 근거를 확인했다는 결과다.

## 같은 DB에서 별도로 확인한 검색·판정 규칙

아래 항목은 정해진 단서를 직접 넣고 API 호출 없이 확인했다. 여섯 항목 모두 기대대로 동작했다.

| 확인 항목 | 결과 |
| --- | --- |
| 브랜드가 빈 흰 이어폰에 `흰색`, `이어폰`, `애플` 입력 | 흰 이어폰 `M01`은 색상·품목 일치로 후보에 남았다. 브랜드는 점수나 탈락 조건에 반영되지 않았다. |
| 구조화된 브랜드 단서 `애플`만 입력 | 등록 브랜드가 일치하는 물품이 없어 `no_candidates`가 반환됐다. |
| 브랜드 키가 빠진 책갈피 | 색상·품목 단서로 `M04`를 찾았다. |
| 보관 조건을 충족하지 않는 헬멧 | 검색에서 제외됐다. |
| 가방 후보가 검색 한도를 초과 | `refine_search`가 반환됐다. |
| 공개된 재질만으로 우산 후보를 좁힘 | 다섯 후보 중 `U01`이 남았지만 비공개 일치 근거가 0개여서 `insufficient_evidence`로 종료됐다. |

추가로 실제 Gemini가 추출한 `보라색`, `바이올린` 단서를 고정하고, DB 물품 하나의 `description`만 `보라색 바이올린`으로 바꿔 검색했다. 변경 전후 모두 `no_candidates`였고, 변경 사항은 되돌렸다.
