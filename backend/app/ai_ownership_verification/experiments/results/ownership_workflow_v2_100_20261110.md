# 유사 물품 검색과 5지선다 소유 확인 실험

2026-11-10에 합성 물품 100개가 들어 있는 별도 SQLite DB와 실제 Gemini `gemini-3.5-flash-lite`로 `development_v2`를 검증했다. 일반 물품 25개, 비슷한 물품 25개, 특징이 일부 비어 있는 물품 40개, 보관 조건을 충족하지 않는 물품 10개였다. 각 검색에서는 보관 중인 90개 물품의 특징을 비교했다. 검색 비교에서 등록 요약 `description`은 제외했다.

## 최종 결과

최종 코드로 전체 실행에서 7개 중 5개가 통과했다. 미완료된 2개 사례를 같은 코드로 재실행해 두 사례 모두 통과했다. 두 실행에서 실제 API 요청은 각각 19회와 6회였다.

| 검증 항목 | 예상 | 관찰 결과 |
| --- | --- | --- |
| 도서관 필통, 비공개 특징 전부 정답 | 5개 후보에서 1개를 확인하고 `supported` | 장식과 문구에 답한 뒤 `5 → 5 → 1`로 줄었다. 재질·브랜드·색상까지 맞혀 5/5에서 확인됐다. |
| 수첩, 비공개 특징 두 개 오답 | 첫 오답 뒤 계속 질문, 두 번째 오답에서 `not_confirmed` | 첫 답변 이후 수첩이 남았고 두 번째 오답에서 제외됐다. |
| 수첩, 오답 1개·정답 1개 | 모든 질문 뒤 `insufficient_evidence` | 수첩이 후보로 남았고 판정을 보류했다. 첫 실행은 단서 추출에서 HTTP `503`으로 미완료됐다. |
| ‘진한 파란색 필통’ | `navy` 필통만 검색 | 품목·색상으로 `P01`만 찾았다. |
| ‘가방’ | 가방 후보 10개 반환 | 미리 정한 후보 10개를 모두 반환했다. |
| ‘흰색 애플 이어폰’, DB의 브랜드가 비어 있음 | 품목·색상으로 `M01`을 찾고 브랜드 일치는 기록하지 않음 | `M01`을 품목·색상으로 찾았다. 첫 실행에서는 모델 응답에 원문에 없는 단서가 있어 서버가 검색 전에 거부했다. |
| ‘보라색 바이올린’ | `no_candidates` | 후보가 없었다. |

실제 실험에서 제출한 객관식은 총 9문항이었고, 모든 문항에 중복 없는 선택지 5개가 있었다. 필통의 첫 장식 질문에는 실제 등록 값 3개와 Gemini가 만든 오답 2개가 포함됐다. 후보가 한 개가 된 뒤 브랜드 질문에는 실제 등록 값 `Carhartt`와 Gemini가 생성한 오답 4개가 포함됐다. 답변은 실험에서 미리 정의한 사용자 시나리오대로 선택했다.

## 초기 실행에서 발견한 문제

- 초기 후보 비교 요청은 Gemini가 응답 규격을 거부했다. 외부 요청 규격을 단순화하고 서버의 응답 검증을 유지해 해결했다.
- 초기 색상 비교에서는 `navy` 필통을 찾았지만 색상이 다른 검은 필통 4개도 함께 반환됐다. 품목만 일치하고 알려진 색상이 명확히 다르면 제외하도록 비교 기준을 보완했다. 최종 실행의 동일 사례에서 검은 필통은 제외됐다.
- 원문 밖의 추출 결과와 HTTP `503`은 두 사례에서 실제로 발생했다. 이번에는 해당 사례를 별도로 재실행했다.

## 재실행

Gemini 키와 모델이 설정된 상태에서 `backend` 폴더에서 실행한다. 출력 폴더는 새 경로로 지정한다.

```powershell
python -m app.ai_ownership_verification.experiments.run_ownership_live --output-dir .pytest_cache/ownership-v2-rerun --max-requests 25
```
