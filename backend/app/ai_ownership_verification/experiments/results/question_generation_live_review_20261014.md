# Gemini 실제 질문 생성 결과 검토

실험·최초 검토일: 2026-10-14 (한국 시간) · 문서 정리일: 2026-10-20

로컬 환경에 설정한 키를 사용해 합성 데이터만 Gemini에 전송했다. API 키·요청 헤더는 기록에 포함하지 않는다. 원본 자동 기록은 보존하고 응답에서 발견한 문제와 검토 의견을 아래에 정리했다.

| 반복 비교 | 전체 6개 사례×2회 | 6회 | [JSON](question_generation_live_repeat_20261014.json) · [요약](question_generation_live_repeat_20261014.md) |

모델: `gemini-3.5-flash-lite`. 각 응답의 modelVersion도 동일했다. 실행 기준 커밋은 `5f9c4da`이며 호출 코드는 실행 당시 미커밋 상태였다. 원본 JSON의 source_hashes로 사용한 코드·입력·프롬프트를 식별한다.

30초 제한, 출력 4096토큰 제한, 제공자 기본 생성 온도, 자동 재시도 0회로 실행했다. 실제 호출 당시 설정·응답·토큰 사용량은 원본 JSON에 보존한다.

## 2. 수치와 해석

- 실제 API 요청 7회 모두 정상 완료. JSON·완료 상태·특징 참조·전체 정답 문자열 노출 검사를 통과했다.
- 정보 부족 로컬 처리 6건. API를 호출하지 않았다.
- 처리 기록 13건 중 기대 상태 일치 12건. 실제 API 응답만 보면 7건 중 6건 일치했다.
- 생성 질문은 총 9개다.
- 실제 요청 처리 시간 최소 3.324초, 최대 6.285초, 평균 5.339초. 로컬 처리 기록은 시간 집계에서 제외했다.
- 입력 토큰 2,898개, 출력 토큰 657개, 제공자 총 토큰 3,555개. 실제 청구 금액은 확인하지 않았다.

이는 소수 합성 사례의 호출·처리 결과이다. 실제 소유자·비소유자의 답변을 평가하지 않았으므로 소유 확인 정확도를 나타내지 않는다.

위 검토는 출력 문구를 입력 특징·프롬프트와 비교한 것이다. 실제 소유자가 답할 수 있는지, 비소유자가 질문 단서를 이용해 답할 수 있는지는 별도의 사용자 답변 실험이 필요하다.

## 4. 발견한 한계와 후속 수정안

1. **부분 힌트:** 정답 전체 문자열 일치 검사는 “모서리” 같은 일부 위치·형태 힌트를 놓친다. 특징 값의 세부 정보를 질문 문장에 포함하지 않도록 프롬프트를 보강하고 담당자가 확인할 검토 기준을 정한다.
2. **지시문과 관찰 자료의 구분:** 모델이 물품에 실제 적힌 문구 자체를 위험한 입력으로 제외하는 경우가 있었다. “지시를 실행하지 않되 적힌 글의 내용을 소유자에게 물을 수 있음”을 명확히 한 버전으로 반복 비교한다.
3. **반복 일관성:** 동일 입력에서 상태가 달라졌다. 생성 설정·프롬프트 버전을 명시해 추가 반복 실험하되, 현재 2회만으로 변동 확률을 추정하지 않는다.
4. **검토 범위:** 담당자 수동 검토는 아직 미수행이며 JSON의 manual_review 값은 그대로 둔다. 상태 일치·자동 테스트 통과를 품질 합격이나 반환 승인으로 연결하지 않는다.

이번 실행에서는 프롬프트나 샘플의 기대 상태를 결과에 맞춰 사후 수정하지 않았다. 개선 실험은 새 버전과 새 결과 파일로 비교한다.

## 5. 자동 테스트

10/14 main `5f9c4da`와 당시 미커밋 질문 생성 코드를 대상으로 실행한 백엔드 자동 테스트는 소유 확인 테스트 42개를 포함해 **78개 통과, PostgreSQL 전용 3개 건너뜀**이었다. SQLite와 httpx 가짜 응답으로 실행했고 실제 Gemini 실험과 구분한다. Starlette TestClient의 AnyIO 사용 관련 DeprecationWarning 1개가 있었다.

~~~powershell
python -m pytest -q --basetemp=.pytest_cache/ownership-live-check
~~~

TEST_DATABASE_URL은 미설정 상태였다. PostgreSQL 행 잠금·동시성, 실제 사용자 답변 평가, 공개 API·DB 연동·반환 코드·보관함 제어는 이번 검증에 포함하지 않는다.
