# 백엔드 구현 현황

작업 단위별 진행 상황과 그때의 결정을 남긴다. 현재 동작과 API는 [기능 명세](functional-spec.md), 물리 스키마는 [ERD](erd.md)를 따른다.

반환 코드 발급·수령 개방·수령 완료가 추가되어 보관한 물건을 다시 꺼내는 한 바퀴가 돌아간다. 발급에 소유 확인 선행 조건이 없고, 질문 생성은 여전히 독립 실험이며 이미지 AI·답변 평가는 업무 흐름에 연결되지 않았다.

## 사용자 결정

- D10: 등록 생성·촬영·분석·개방·완료를 별도 API로 구현하고 UUID·상태·중복 배정 방지 구조를 채택한다.
- D11: 등록·촬영·보관·검색 준비까지를 먼저 구현한다. AI는 교체 가능한 연결부로 준비한다. 소유 확인·반환 코드·수령은 보류한다(반환 코드·수령은 이후 P06~P08에서 구현).
- D12: 카테고리 필수 여부와 공개 범위는 아직 확정하지 않는다. 등록 입력은 선택값으로 저장하고 검색은 내부 서비스까지만 구현한다. 공개 검색 API는 보류한다.
- D13: 업무 API는 기본 비활성화하고 명시적인 로컬 개발 설정에서만 활성화한다. 실제 장치·공개 배포 전 인증은 별도로 연결한다.

## 구현된 범위

| 작업 | 구현 범위 |
| --- | --- |
| P00 | FastAPI 의존성 교체, 테스트 전용 Pi·저장소·AI, 정상/실패 시나리오. 실행 앱에는 가짜 AI를 등록하지 않음 |
| P01 | 키오스크·카테고리 조회, 선택 입력 등록 생성/조회, UUID·FK·상태 제약, 명시적 로컬 시드 |
| P02 | 순차 촬영 2회, JPEG 디코딩·크기 검증, 비공개 S3 어댑터, 객체 키/메타데이터 저장, 임시 미리보기 URL |
| P03 | 두 사진 바이트/ID를 AI 경계로 전달, 결과 대상·순서·특징 JSON 검증, 결과 저장. 실제 AI 성공 스키마는 미정 |
| P04 | 분석 성공 및 사진 일치 확인, 빈 칸 원자적 예약, 명령 선저장, Pi opened 검증, 완료 확인+closed, 중복 요청 억제 |
| P05 | 로컬 키오스크 위치 조회. 보관 완료 물건의 내부 필터·페이지네이션. 공개 검색 경로 없음 |
| P06~P08 | 반환 코드 발급·검증·수령 개방·수령 완료와 배정 종료 구현. 소유 확인 평가와 실제 시스템 통합은 미포함 |

DB는 `kiosks/categories/lockers/registrations/item_images/device_commands/found_items/storage_assignments/return_codes` 9개 테이블이다. AI 특징은 등록의 `analysis_features` JSONB에 원본 입력과 구분해 저장한다. 별도 `devices/item_features/verification_attempts` 테이블은 아직 필요하지 않아 추가하지 않았다. `return_codes`는 코드 평문 대신 SHA-256 해시만 저장하며 질문·답변·판정 FK가 없다. 분석 입력 ID는 서비스에서 검사하며 JSON 내부 참조를 FK로 보호하지는 않는다.

장치 주소는 이번 로컬 구현에서 `PI_DEVICES` 설정으로 전달한다. Pi 내부 경로에는 보관함 UUID가 아닌 키오스크 안의 정수 `locker_number`를 사용한다. 물건·칸의 유효 배정은 부분 UNIQUE 인덱스로 중복을 방지한다. 배정 선택에는 PostgreSQL 키오스크 행 잠금으로 가용성 조회를 직렬화하고, 칸 행 잠금과 `SKIP LOCKED`를 함께 사용한다. 외부 호출 전에 트랜잭션을 종료하므로 Pi 응답을 기다리는 동안 배정 잠금을 유지하지 않는다.

## 합의 전 보수적으로 유지하는 제한

- 재촬영·사용자 취소·예약 만료·자동 해제·하드웨어 재시도, 결과 불명으로 잠긴(`locked`) 반환 코드의 해소는 구현하지 않았다. 명확한 개방 실패도 배정을 보존한다. 응답 유실은 `unknown`, 명시적 장치 실패는 `failed`로 남긴다.
- 외부 작업 전 등록 진행 상태와 명령을 커밋한다. 프로세스/DB 장애로 결과를 기록하지 못하면 진행 상태와 `sent`가 남아 재실행을 막는다. 이 상태를 정상/빈 칸으로 자동 간주하지 않는다.
- S3 업로드 성공 후 DB 기록에 실패하면 명령 ID로 된 객체가 남을 수 있다. 자동 삭제·보존 기간은 Q07/Q11 합의 전 미구현이다. 복구 시 등록/명령/배정과 실제 장치를 함께 대조해야 한다. 임의 DB 초기화나 새 개방 명령으로 복구하지 않는다.
- 분석 실패는 촬영 이미지가 유지된 `draft`로 돌아가 명시적 분석 재요청이 가능하다. 프로세스 중단으로 남은 `analyzing`은 자동 해제하지 않는다.
- 작은 칸 번호 우선, 2,000자 입력 제한, 내부 검색 limit 20/최대 100은 로컬 구현 선택이며 최종 정책 확정이 아니다. 명령 TTL·HTTP 시간 제한·이미지 크기·서명 URL 만료는 설정 없이는 해당 연동을 사용하지 못한다.
- 실제 Pi·S3·AI 연결, 공개 인증, CORS/FE 배포 출처, 재시도/복구/보존, 최종 카테고리·공개 검색 계약은 후속 합의가 필요하다.
