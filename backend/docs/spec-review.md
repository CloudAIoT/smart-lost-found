# 명세 검토와 결정 기록

검토일: 2026-10-08 · 기준 커밋: `3aebe307dbdc8ebf4ae08ec90e1737317af170b5`

검토 범위는 [근거 문서 목록](README.md)에 기록했다. `main`의 원문을 비교하고 현재 구현과 대조했다. 새 문서는 원문을 대체하는 팀 합의서가 아니라 백엔드 개발을 위한 검토 자료이다. [기능 명세](functional-spec.md)와 [ERD](erd.md)의 제안을 구현 전에 검토한다.

D03·D06은 실제 물건의 존재를 문 센서만으로 입증한다는 뜻이 아니다. 성공한 개방 이후 사용자가 완료를 확인했다는 사실과 닫힌 문을 업무 완료의 근거로 삼는 결정이다. 소유 확인 방식이나 사용자 본인인증 결정을 대신하지 않는다.

D08·D09로 기존에 미정이었던 특징 기반 질문 생성·AI 답변 평가의 방향과 담당 범위가 구체화되었다. 질문 수·입출력 필드·평가 기준·반환 코드 발급 조건까지 확정한 것은 아니다. 원문 S5의 과거 미정 기록은 이 결정과 구분해 읽는다.

## 3. 로컬 참고 문서와의 차이

`output/documents/`의 Word 문서들은 검토 시작 시 Git 미추적 파일이었다. 파일명·문서 날짜만으로 main보다 우선한다고 판단하지 않았다(D01). 작업 중 해당 파일을 수정하거나 버전 관리에 추가하지 않았다.

비교 대상 중 `Software_Architecture_Document_회의반영_카메라1대_20261007.docx`는 v1.2 회의 반영안·개정 검토 대기로 표시되어 있다. 본문과 테이블의 관련 절을 읽어 다음 차이를 확인했다. 문서 레이아웃이나 외부 참고 자료의 유효성을 검증한 것은 아니다.

| 항목 | 로컬 참고 문서 | main 기준 또는 사용자 결정 |
| --- | --- | --- |
| 등록당 사진 수 | 1장 또는 다각도 반복 중 선택, 2장 필수 아님 | S1·S2·S4의 순차 촬영 2장 적용 |
| 촬영 성공 응답 | JSON에 image 객체와 base64 JPEG 제안 | S2의 200 `image/jpeg` 바이너리 적용 |
| 촬영 시각 | JSON `captured_at` 제안 | S2에는 필드 없음. 백엔드 수신 시각과 구분 |
| 신원 인증 | 실명·얼굴 인증 제외 | S1과 D02에 따라 미정 유지 |
| 소유 확인 | 비공개 특징 기반 질문·답변 중심 | S5는 미정이었으나 후속 D08·D09로 특징 기반 질문 생성·AI 답변 평가 방향 결정. 상세 계약은 미정 |
| AI 실행 | 자체 모델 별도 서버 또는 기반 모델 API 선택 | 이미지 분석 방식 미정. 소유 확인 Gemini 사용은 S5에 명시 |
| 원본 이미지 저장 | 비공개 S3 제안 | main에는 미지정이었으나 이번 D07로 선택 |
| ERD·명령 상태 | 개념 관계와 명령 상태 제안 | 참고하되 이번에도 검토용 설계로 명시 |
| 배포·성능·복구 목표 | EC2·Vercel, 응답·정확도·RTO/RPO 목표 제안 | main의 확정 요구로 옮기지 않음. 이번 백엔드 문서 범위에서 추가 확정 안 함 |

다른 이전 버전의 두 카메라·top/side 촬영안을 현재 설계로 가져오지 않는다. main의 S4가 단일 카메라 2회 촬영을 결정 기록으로 남기고 있다.

## 5. 합의 후 반영할 위치

- 문 닫힘 방식 D03·D06: S2 7절과 FE 완료 버튼 계약에 반영해야 한다.
- 분석 성공 선행 D04: S2 6.1, S1 등록 흐름, 이미지 처리 AI의 성공·오류 계약에 반영해야 한다.
- S3 저장 D07: 등록·미리보기 API와 배포 설정·접근 정책을 함께 정해야 한다.
- 소유 확인·코드 계약 Q05·Q06: S5의 미정 목록과 루트 `docs/api.md`를 함께 갱신해야 한다.
- 장치 계약 Q09·Q10: 루트 `docs/device-protocol.md`와 Pi 구현의 같은 버전에 반영해야 한다.

이번 작업에서는 요청한 `backend/docs/`와 백엔드 README의 안내 링크만 변경한다. 원본 공통 문서의 협의 항목이 이미 팀 합의로 확정된 것처럼 수정하지 않는다.
