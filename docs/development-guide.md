# \# 개발 및 Git 사용 안내

# 

# \## 1. GitHub 작업

# 

# GitHub에서 공동개발하고, 커밋 메시지에는 작성자 정보를 넣는다. 아래처럼 이름과 작업 내용을 적으면 된다.

# 

# ```text

# by 김선재 - 분실물 등록 API 구현

# by 김선재 - 이미지 업로드 오류 수정

# by 김선재 - 테스트 결과 정리

# ```

# 

# 명령 예시:

# 

# ```bash

# git commit -m "by 김선재 - 분실물 등록 API 구현"

# ```

# 

# \### 현재 저장소에서 작업하는 방법

# 

# 최신 main 확인 → 작업 브랜치 생성 → 구현·테스트 → 커밋·push → PR에서 코드리뷰 → main 반영

# 

# 이 흐름은 기존 PR 방식을 이어 쓰기 위한 작업 방법이다. 교수님이 PR 사용이나 형식을 지정한 것은 아니다.

# 

# Issue는 따로 작성하지 않아도 된다. 브랜치명, 커밋의 feat/fix 구분, PR 양식·승인 인원, 병합 방식도 별도 필수 규칙으로 두지 않는다. 커밋의 작성자 표시는 지킨다.

# 

# \## 2. 문서와 참여 기록

# 

# 작성한 코드와 개발 문서는 GitHub에 올린다. 개발 문서는 현재 저장소의 docs/에 모은다.

# 

# 교수님은 GitHub 로그로 개인 참여도를 평가하므로, 각자 수행한 작업이 기록에 남도록 한다. 최종 발표 때 개발 시스템에 대한 상호작용 기록(GitHub 로그)을 제출한다.
