# 문서작성목적
본 문서는 Frontend 단에서 구성하는 웹과 키오스크용 사이트의 구조를 정의하고 구현할 기능의 범위를 설정하는 문서이다.

## 용어 의미
1차 카테고리: 물건의 종류를 서술할 때 사용되는 이어폰, 노트북, 가방 등의 가장 넓은 분류 기준을 의미한다. 색, 문양 등의 정보는 2차 카테고리로 분류한다.

RP: Raspberry Pi의 약어.

FE: Frontend의 약어. 맥락에 따라 Frontend 파트 혹은 개발자를 의미한다.

BE: Backend의 약어. 맥락에 따라 Backend 파트 혹은 개발자를 의미한다.

## 시스템 UI 개요
접속 경로는 휴대폰 웹 포털 `/web`, 현장 단말 `/kiosk`, 운영자 장치 상태 `/admin/devices`, 단말 설정 `/kiosk/settings`로 분리한다. 일반 이용 화면에는 모드 전환·관리 화면 링크를 두지 않는다. 관리자는 별도 URL이나 북마크로 접속한다. `/admin/devices`는 서버 관리자 인증 후 경고 검토·조치 이력을 제공한다. `/kiosk/settings`의 경로 구분은 인증 기능이 아니며, 업무 중 또는 운영 중단 중에는 설정 변경을 차단한다.

미해결 alarm은 해당 키오스크 전체 업무를 중단한다. 사용자가 닫을 수 없는 관리자 대기 모달을 표시하고 서버 업무 API도 차단한다. warning은 사용자 확인으로 숨길 수 있다. 관리자의 문제 해결 확인과 조치 기록 뒤 모든 alarm이 해결되면 재개한다. [F14 운영 중단과 관리자 조치](../backend/docs/functional-spec.md#f14-운영-중단과-관리자-조치)를 따른다.

* 웹
  사용자가 휴대폰으로 접속하게 될 웹사이트에는 습득자에게는 습득물을 넣을 키오스크 위치를 조회할 수 있도록 하고, 분실자에게는 자신이 잃어버린 물건의 카테고리를 입력하여
  자신의 물건이 어느 분실물 보관함에 있는지를 조회하고 질문을 통해 자신의 분실물을 찾을 수 있는 인증수단을 제공한다.
  인증방식에 대한 결정권한은 기본적으로 FE 개발자에게 있으나, 팀원 간 협의를 통해 방식을 확정하는 것으로 한다.
* 키오스크
  키오스크는 분실물 보관함과 연동하여 등록과 수령 절차를 진행하는 UI이다. 테스트·시연용 화면에서는 아래 FE-K01의 최초 설정으로 사용할 키오스크를 지정한다. 이 설정은 습득자의 본인인증이나 기기 인증을 대신하지 않으며, 본인인증 도입 여부는 별도 협의 사항이다.
  이후 분실물을 넣을 수 있게 보관함 번호를 알려주고, 분실자에게는 웹에서 획득한 인증수단을 인식시킨뒤 해당 물건이 들어있는 보관함의 번호를 띄워준다.

## 시스템 기능 구현 범위
FE 단에서는 사용자입력과 이벤트 처리에 초점을 맞추고 해당 처리를 위해 BE에 요청을 보낸뒤 적절한 응답을 받는것을 기본 동작 구조로 삼는다.

### FE-K01 키오스크 최초 1회 설정

2026-11-18 명세 추가, 2026-11-25 FE 구현 반영. **테스트·시연용 FE 구현 범위**다. 키오스크 선택을 최초 설정으로 확정하고, 선택한 `kiosk_id`를 같은 브라우저에서 기억한다. 백엔드 API·DB 변경 없이 구현한다. 기기별 페어링·인증은 아래 후속 범위로 분리한다.

`frontend/src/App.jsx`의 `KioskView`와 `kioskSettings.js`가 아래 복원·확정 절차를 적용한다. `/kiosk` 직접 진입과 새로고침도 동일한 절차를 따른다. 웹 포털에서 위치를 탐색하거나 반환 코드에 연결된 키오스크를 보는 동작은 이 단말 설정을 변경하지 않는다.

#### 저장 계약

| 항목 | 규칙 |
| --- | --- |
| 저장소·키 | `localStorage`의 `smart-lost-found.kiosk_id.v1` |
| 저장값 | 사용자가 확정한 키오스크 UUID 문자열 하나 |
| 표시 정보 | 키오스크 이름·위치는 매번 `GET /api/kiosks` 결과에서 가져온다 |
| 유지 범위 | 동일 출처(프로토콜·호스트·포트)의 동일 브라우저 프로필. 새로고침·브라우저 재실행·웹/키오스크 모드 전환 후에도 복원 |
| 초기화 시점 | 사용자가 설정을 초기화하거나, 목록 조회 성공 후 저장된 ID가 더 이상 존재하지 않는 것으로 확인된 때 |
| 저장하지 않는 값 | Pi API 키, 반환 코드, 소유 확인 답변, 등록 사진·특징, 진행 중인 등록·수령 정보 |

다른 브라우저·프로필, 저장소 삭제, 시크릿 모드 종료, HTTP에서 HTTPS로 변경 등으로 저장값을 사용할 수 없으면 최초 설정부터 진행한다. 이번 범위는 키오스크 선택 복원이며, 진행 중이던 등록·수령 절차나 웹/키오스크 화면 모드의 새로고침 복구는 별도 과제다.

#### 최초 선택과 복원

1. 키오스크 화면 진입 시 저장값을 읽고 키오스크 목록을 조회한다. 확인 중에는 등록·수령 시작 버튼을 비활성화하며, 저장된 ID만으로 장치 관련 요청을 보내지 않는다.
2. 목록은 `GET /api/kiosks?limit=100&offset=0`부터 읽는다. 한 페이지가 100건이면 `offset`을 100씩 증가시켜 100건 미만의 페이지가 나올 때까지 조회한다. 첫 페이지에 ID가 없다는 이유만으로 저장값을 무효 처리하지 않는다. `App.loadData`는 `loadAllKiosks`를 통해 이 규칙을 적용한다.
3. 저장값이 없거나 UUID 형식이 잘못되었으면 최초 설정을 표시한다. 드롭다운에는 이름과 장소를 함께 표시하고, 사용자가 선택 후 **이 키오스크로 설정**을 눌러야 저장한다. 목록이 한 건이어도 확인을 받으며 첫 항목을 자동 확정하지 않는다.
4. 저장된 ID가 목록에 있으면 해당 키오스크를 복원하고 선택 화면을 건너뛴다. 상단에는 현재 키오스크 이름·장소를 계속 표시한다. 복원 자체로 촬영·분석·개방 API를 자동 호출하지 않는다.
5. 전체 목록 조회에 성공했는데 저장된 ID가 없으면 해당 저장값을 제거하고 재설정을 안내한다. 목록이 비어 있으면 이용할 수 없다는 안내와 목록 새로고침을 제공한다.
6. 네트워크·서버 오류로 목록 조회가 실패하면 저장된 ID를 유지하고 재시도를 안내한다. 다른 키오스크로 자동 변경하거나 기존 목록을 근거로 등록·수령을 시작하지 않는다.
7. `localStorage` 읽기·쓰기·삭제는 예외를 처리한다. 저장할 수 없는 브라우저에서는 목록으로 확인하고 선택한 ID를 현재 화면의 메모리에서만 사용할 수 있다. 이때 **이 브라우저에서는 설정을 저장할 수 없어 다음 접속 때 다시 선택해야 합니다**라고 표시한다. 삭제 실패를 초기화 성공으로 표시하지 않는다.

#### 변경과 업무 요청

- **키오스크 변경 / 설정 초기화**는 별도 `/kiosk/settings`에서만 제공한다. 업무 중 내부 이동·뒤로가기로 설정 화면에 진입할 수 없고, 대기 상태나 업무 완료 후 이용할 수 있다. 최초 미설정 상태의 선택·확정은 `/kiosk`에서도 제공한다. 변경 선택은 저장을 확정하기 전까지 기존 설정에 영향을 주지 않는다. 초기화는 해당 저장 키만 지우며 `localStorage.clear()`로 다른 데이터를 지우지 않는다.
- 등록 시작부터 보관 완료까지, 수령 시작부터 수령 완료까지 사용할 키오스크를 고정한다. 요청 중이거나 등록·수령 건이 남아 있으면 오류 화면에서도 변경하지 못하게 한다. 화면을 초기화하는 것만으로 서버의 등록·배정이 취소된 것으로 취급하지 않는다.
- 요청 직전에 매번 `localStorage`를 다시 읽어 대상을 바꾸지 않는다. 같은 출처의 다른 탭에서 저장값이 바뀌더라도 진행 중인 업무의 대상에는 적용하지 않고 대기 상태에서 재검증한다.
- 기존 `KioskView.reset()`으로 다음 사용자를 맞이할 때는 등록·수령 입력만 비우고 키오스크 설정은 유지한다.

| API | 키오스크 적용 규칙 |
| --- | --- |
| `POST /api/registrations` | 검증·확정된 단말 설정의 `kiosk_id`를 본문에 넣는다. 성공한 응답의 등록 ID와 키오스크 ID를 해당 업무에 연결한다 |
| `/api/registrations/{id}/shots/{order}`, `/analysis`, `/deposit/open`, `/deposit/complete` | 같은 등록 ID를 계속 사용한다. 이 API들에 `kiosk_id`를 새로 붙이지 않으며, 백엔드가 등록에 저장된 키오스크로 장치를 선택한다 |
| `POST /api/pickup/open` | 사용자가 입력한 반환 코드와 검증·확정된 단말 설정의 `kiosk_id`를 함께 보낸다 |
| `POST /api/pickup/{found_item_id}/complete` | 개방 응답으로 받은 물품 ID를 사용한다. 수령 도중 다른 키오스크로 설정을 바꾸지 않는다 |

수령 요청이 `RETURN_CODE_WRONG_KIOSK`로 거절되면 **이 키오스크에서 수령할 수 없는 코드입니다**라고 안내한다. 코드를 맞추기 위해 단말의 키오스크 ID를 자동 변경하지 않는다.

#### 편의 설정과 기기 인증의 경계

`localStorage` 값은 사용자가 바꿀 수 있는 편의 설정이다. UI에서도 **로그인**, **기기 인증 완료** 대신 **키오스크 설정**으로 표현한다. 이름·위치 표시와 드롭다운 제한은 실수를 줄이지만 요청자의 현장 위치나 장치 신원을 증명하지 않는다.

현재 백엔드는 호출자의 기기 신원을 인증하지 않는다. 등록의 분석·상태 조건, 반환 코드·소유 확인 및 대상 키오스크 일치 검사는 존재하지만, 조건을 만족하는 요청을 실제 현장 단말이 보냈는지는 검증하지 않는다. 따라서 이 FE 변경만으로 다른 장소에서 보내는 촬영·개방 요청을 막을 수 없다.

기기 인증을 도입할 때 필요한 후속 범위는 다음과 같다. **현재 API에 이미 있는 기능으로 취급하거나 FE가 임의의 토큰 필드를 보내지 않는다.**

- 운영자가 승인한 기기에 한정한 최초 페어링과, 서버가 특정 `kiosk_id`에 묶어 발급하는 기기 자격증명.
- 등록·촬영·분석·투입 개방/완료·수령 개방/완료 요청에서 인증된 기기와 대상 키오스크의 일치 확인. 경로의 등록 ID·물품 ID도 서버에서 소속을 확인하며, 본문의 `kiosk_id`만 신뢰하지 않는다.
- 자격증명의 만료·폐기·재페어링과 분실·교체 시 처리. 인증 자체가 물리적 현장 존재까지 보장하는 것은 아니므로 필요한 현장 조건은 별도로 정한다.
- 기기 인증용 자격증명과 서버→Pi의 `PI_API_KEY`는 분리한다. Pi 키를 프론트 코드·`VITE_*` 환경 변수·브라우저 저장소에 넣지 않는다. 페어링 API, 자격증명 전달·보관 방식, 인증 오류 계약은 BE·FE·운영이 후속 설계에서 정한다.

#### FE 인수 확인

| 시나리오 | 기대 결과 |
| --- | --- |
| 저장값 없는 첫 접속 | 선택·확정 전 업무 시작 불가, 한 건이어도 사용자 확인 필요 |
| 키오스크 B 확정 후 새로고침·재접속·모드 전환 | B 복원, 이름·장소 표시, 첫 항목 A로 바뀌지 않음 |
| 저장된 ID가 목록의 두 번째 페이지에 있음 | 모든 페이지 조회 후 복원, 설정을 잘못 삭제하지 않음 |
| 목록 조회 실패 또는 중간 페이지 실패 | 저장값 유지, 오류·재시도 표시, 업무 시작 차단 |
| 저장 ID의 형식 오류 또는 전체 목록에서 삭제 확인 | 다른 키오스크 자동 선택 없이 재설정 안내 |
| 저장소 접근 불가 | 화면 오류 없이 현재 선택 사용 가능, 영구 저장 실패 안내 |
| 등록·수령 진행 중 변경 시도 또는 다른 탭의 설정 변경 | 현재 업무의 키오스크·등록·물품 연결 유지 |
| 업무 완료 후 다음 사용자 시작 | 업무 입력은 초기화하고 키오스크 설정은 유지 |
| 다른 키오스크의 반환 코드 입력 | `RETURN_CODE_WRONG_KIOSK` 안내, 자동 전환·추가 개방 요청 없음 |
| 대기 상태에서 설정 초기화 | 설정 키만 삭제하고 최초 선택 화면으로 복귀 |

### 웹(습득자) 
* 키오스크 위치 조회기능 - 오픈소스 지도 API 이용. 이용자의 현재 위치 조회 권한 허용 필요

### 웹(분실자)
*  카테고리 입력으로 자신의 물건 위치를 조회하는 기능 - 카테고리가 입력되면 BE 데이터베이스에 해당 카테고리의 물건이 있는지 조회요청.
  BE의 응답을 받아 키오스크의 위치를 띄워줌.

### 키오스크(습득자)
* 촬영용 공간 투입 지시 기능 - 키오스크 설정을 확인하고 등록 절차를 시작하면 상시 개방 되어있는 촬영용 공간에 물건을 넣어달라는 UI를 사용자에게 띄운다. 촬영한 사진은 FE를 거치지않고
  곧바로 RP to Backend로 이동한다. 하드웨어 장비 상의 한계로, 촬영에 가용가능한 카메라의 대수가 1대이므로 1회 촬영이후 각도를 바꾸어 달라는 지시를 사용자에게 띄워준다. 현재 단계에서 총 2장의 서로다른 각도에서의 사진을 촬영하게 되며 물건의 각도를 얼마나 돌려야할지는 이미지 처리 AI파트 개발자가 실험을 통해 실험을 통해 도출한 최적 각도 기반 가이드라인을 UI에 띄워주는 것으로 한다.

* 분실물 보관함 번호 제시 기능 - 촬영 이후 BE에 현재 비어있는 보관함 번호 조회 요청. BE는 FE에서 요청을 받으면 곧바로 응답을 하지 않고 우선 해당하는 보관함 번호를 열어달라는 요청을 RP에게 먼저 보낸다. 해당하는 번호가 성공적으로 열렸다는 응답이 BE로 전송이 되었을 때, BE는 프론트 엔드에 보관함 번호를 응답으로서 전달하고 이 번호를 UI에 띄워준다.

### 키오스크(분실자)
* 인증수단을 통한 보관함 번호 제시 기능 - 웹에서 사용자가 얻은 인증수단을 UI에 입력하면 해당 정보를 BE에 넘긴다. 이후 BE는 라즈베리파이에게 같은 번호의 보관함을 열어달라는 요청을 보내고 RP는 해당 물건이 들어있는 보관함을 개방시킨다. RP to Backend로 개방 성공신호가 전달되면 인증번호에 해당하는 보관함의 번호를 FE단에 응답으로서 전달한다. FE는 이 번호를 UI에 띄워준다.

## 기능 세부 사항
카테고리는 사전에 정의된 1차 카테고리들과 습득자가 직접 입력할 수 있는 2차 카테고리 2가지의 형태로 입력을 받는다.

## 협의 필요 내용
분실물 습득자의 본인인증 여부는 추후 법적책임등을 요구하기 위해 필요하다고 생각이 되나 인증 자체로 인해 본 시스템을 사용하는 것을 꺼려하는 사용자의 입장을 고려. 협의를 통해 결정하는 것으로 한다.
