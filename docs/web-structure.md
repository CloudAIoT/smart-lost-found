# 문서작성목적
본 문서는 프론트엔드 단에서 구성하는 웹과 키오스크용 사이트의 구조를 정의하고 구현할 기능의 범위를 설정하는 문서이다.

## 용어 의미
1차 카테고리: 물건의 종류를 서술할 때 사용되는 이어폰, 노트북, 가방 등의 가장 넓은 분류 기준을 의미한다. 색, 문양 등의 정보는 2차 카테고리로 분류한다.
RP: Raspberry Pi의 약어.

## 시스템 UI 개요
* 웹
  사용자가 휴대폰으로 접속하게 될 웹사이트에는 습득자에게는 습득물을 넣을 키오스크 위치를 조회할 수 있도록 하고, 분실자에게는 자신이 잃어버린 물건의 카테고리를 입력하여
  자신의 물건이 어느 분실물 보관함에 있는지를 조회하고 질문을 통해 자신의 분실물을 찾을 수 있는 인증수단을 제공한다.
  인증방식에 대한 결정권한은 기본적으로 프론트엔드 개발자에게 있으나, 팀원 간 협의를 통해 방식을 확정하는 것으로 한다.
* 키오스크
  키오스크는 분실물 보관함과 연동하여 실제로 물건의 수령 절차를 진행하는 UI이기 때문에 습득자에게는 본인인증 후 물건을 카메라에 인식할 수 있게 촬영용 공간을 개방한다.
  이후 분실물을 넣을 수 있게 보관함 번호를 알려주고, 분실자에게는 웹에서 획득한 인증수단을 인식시킨뒤 해당 물건이 들어있는 보관함의 번호를 띄워준다.

## 시스템 기능 구현 범위
프론트엔드 단에서는 사용자입력과 이벤트 처리에 초점을 맞추고 해당 처리를 위해 백엔드와 라즈베리파이에 요청을 보낸뒤 적절한 응답을 받는것을 기본 동작 구조로 삼는다.

### 웹(습득자) 
* 키오스크 위치 조회기능 - 오픈소스 지도 API 이용. 이용자의 현재 위치 조회 권한 허용 필요

### 웹(분실자)
*  카테고리 입력으로 자신의 물건 위치를 조회하는 기능 - 카테고리가 입력되면 백엔드 데이터베이스에 해당 카테고리의 물건이 있는지 조회요청.
  백엔드의 응답을 받아 키오스크의 위치를 띄워줌.

### 키오스크(습득자)
* 촬영용 공간 투입 지시 기능 - 인증이 끝나면 상시 개방 되어있는 촬영용 공간에 물건을 넣어달라는 UI를 사용자에게 띄운다. 촬영한 사진은 프론트엔드를 거치지않고
  곧바로 RP to Backend로 이동한다. 하드웨어 장비 상의 한계로, 촬영에 가용가능한 카메라의 대수가 1대이므로 1회 촬영이후 각도를 바꾸어 달라는 지시를 사용자에게 띄워준다. 현재 단계에서 총 2장의 서로다른 각도에서의 사진을 촬영하게 되며 물건의 각도를 얼마나 돌려야할지는 이미지 처리 AI파트 개발자가 실험을 통해 최적 각도를 찾는것으로 한다. 실험을 통해 도출한 최적 가이드라인을 UI에 띄워주는 것으로 한다.

* 분실물 보관함 번호 제시 기능 - 촬영 이후 백엔드에 현재 비어있는 보관함 번호 조회 요청. 백엔드는 프론트엔드에서 요청을 받으면 곧바로 응답을 하지 않고 우선 해당하는 보관함 번호를 열어달라는 요청을 RP에게 먼저 보낸다. 해당하는 번호가 성공적으로 열렸다는 응답이 백엔드로 전송이 되었을 때, 백엔드는 프론트 엔드에 보관함 번호를 응답으로서 전달하고 이 번호를 UI에 띄워준다.

### 키오스크(분실자)
* 인증수단을 통한 보관함 번호 제시 기능 - 웹에서 사용자가 얻은 인증수단을 UI에 입력하면 해당 정보를 백엔드에 넘겨 인증번호에 해당하는 보관함의 번호를 응답으로서
  받는다. 동시에 백엔드는 라즈베리파이에게 같은 번호의 보관함을 열어달라는 요청을 보내 해당 물건이 들어있는 보관함을 개방시킨다.

## 기능 세부 사항
카테고리는 사전에 정의된 1차 카테고리들과 습득자가 직접 입력할 수 있는 2차 카테고리 2가지의 형태로 입력을 받는다.

---
## 협의 필요 내용
분실물 습득자의 본인인증 여부는 추후 법적책임등을 요구하기 위해 필요하다고 생각이 되나 인증 자체로 인해 본 시스템을 사용하는 것을 꺼려하는 사용자의 입장을 고려. 협의를 통해 결정하는 것으로 한다.
