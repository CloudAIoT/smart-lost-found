# Frontend (웹 포털 + 현장 키오스크)

React 19 + Vite + Tailwind CSS 3로 만든 단일 페이지 앱이다. 한 화면에서 상단 토글로 두 모드를 오간다.

- **웹 포털**: 습득자용 키오스크 위치 조회(지도), 분실자용 자연어 검색·5지선다 소유 확인·수령 OTP 발급
- **현장 키오스크**: 분실물 등록(정보 입력 → 촬영 2회 → 분석·보관함 개방 → 투입 완료), 분실물 수령(OTP 입력 → 보관함 개방 → 수령 완료)

프론트 구현은 [백엔드 전체 기능 명세](../backend/docs/functional-spec.md)를 기준으로 진행한다. 화면별 등록·검색·소유 확인·사진 확인·수령 순서, 19개 API의 입력·응답·오류, 상태 전이와 인수 시나리오를 정리했다. 빠른 API 참조와 운영자 DB 확인은 [docs/api.md](../docs/api.md)를 따른다. 모든 업무 호출은 같은 출처의 상대 경로 `/api`로 보낸다.

키오스크 선택을 새로고침 후에도 유지하는 FE 구현 명세는 [FE-K01: 키오스크 최초 1회 설정](../docs/web-structure.md#fe-k01-키오스크-최초-1회-설정)을 따른다. 드롭다운 선택을 `localStorage`에 저장하고 목록 조회로 검증해 복원하는 테스트·시연용 편의 기능이며, 기기 인증을 제공하지 않는다. 저장 키, 오류 처리, 업무 중 대상 고정, 인수 확인 항목을 해당 명세에 모았다. 현재 코드는 첫 키오스크를 자동 선택하고 메모리에만 보관하므로 이 명세의 FE 구현은 별도 작업이다.

## 로컬 개발

```bash
cd frontend
npm ci
npm run dev        # http://localhost:5173
```

백엔드에 CORS 설정이 없으므로 개발 서버는 `vite.config.js`의 프록시로 `/api` 요청을
EC2 백엔드(`http://52.78.12.168`)에 넘긴다. 로컬 백엔드를 쓸 때는 `SLF_API_TARGET=http://127.0.0.1:8000`을 개발 서버의 환경 변수로 설정한다.

## 배포

별도 서버가 없다. `deploy/Dockerfile`이 백엔드 이미지를 만들 때 `npm ci && npm run build`로
`dist/`를 만들어 함께 넣고, EC2의 nginx가 `/`에서 정적 파일을, `/api/`는 백엔드로 넘긴다.
프론트와 API가 같은 주소이므로 운영에서도 CORS가 필요 없다. 자세한 내용은 [deploy/README.md](../deploy/README.md).

`main`에 병합되면 기존 배포 워크플로가 백엔드와 함께 배포한다. 접속 주소: `http://52.78.12.168/`

## 현재 제한

- 질문 종료 시 후보가 하나 남으면 등록 사진을 보여 준다. 자동 등록에서 추출된 특징으로도 이 단계까지 진행할 수 있다. 사용자가 사진 속 물건을 본인 것으로 확인하면 수령 OTP를 발급한다. 후보가 여러 개 남으면 소유 확인 실패로 표시한다.
- 수령 OTP는 8자리(현재 백엔드는 Base32 A~Z·2~7)이며 영문 대문자·숫자를 받는다.
- 개발 서버(`npm run dev`)에서만 테스트 OTP `DEV00000`이 동작한다. 백엔드를 호출하지 않고 수령 화면 흐름만 보여 주며, 빌드본에서는 꺼진다.
- 현재 위치(지도)는 HTTPS 또는 localhost에서만 사용할 수 있다. HTTP 배포에서는 키오스크 목록만 보인다.
- 2차 촬영 각도 안내 문구(`SHOT2_GUIDE`)는 이미지 처리 AI 파트의 가이드가 나오면 바꾼다. 1차 촬영 완료 시 이 문구를 팝업으로 띄운다.
- 키오스크 등록은 물건 종류를 등록된 목록에서 고르는 방식이다(자유 입력 없음). 목록이 비어 있으면 종류 없이 바로 촬영 단계로 진행한다. 등록 요청의 `secondary_description`은 보내지 않는다.
- 화면은 터치 기준이다(결정 기록 0005: 키오스크 화면은 촬영 상자 옆 아이패드). 버튼·선택 항목은 최소 44px 터치 영역이고, 입력칸은 16px 이상이라 iOS에서 자동 확대되지 않는다. 스마트폰 웹에서도 같은 화면을 쓴다.
- 확인 화면(사진 2장)에서 "재촬영" 버튼으로 해당 촬영 단계로 돌아갈 수 있다. **다만 `docs/api.md`에 따르면 현재 백엔드는 같은 사진 번호의 저장 완료 요청을 반복하면 새로 찍지 않고 기존 저장 결과를 그대로 반환하며, 재촬영 자체를 아직 지원하지 않는다.** 즉 지금 상태로는 재촬영 버튼을 눌러 다시 촬영해도 백엔드가 이전 사진을 그대로 돌려줄 수 있다. 실제로 사진이 교체되게 하려면 백엔드에 재촬영(같은 `shot_order`의 덮어쓰기) 지원이 먼저 필요하다 — 백엔드 담당자와 협의가 필요하다.
- 촬영 중 카메라 자체 오류(전원 꺼짐 등)로 500이 내려오면 "현재 카메라에 기술적인 문제가 발생하였습니다. 관리자에게 문의하세요." 안내 후 등록 프로세스를 종료(실패 화면 → 처음으로)한다.
