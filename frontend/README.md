# Frontend (웹 포털 + 현장 키오스크)

React 19 + Vite + Tailwind CSS 3와 React Router로 만든 단일 페이지 앱이다. 휴대폰용 웹 포털은 `/web`, 현장 단말은 `/kiosk`로 직접 접속하며 `/`는 `/web`으로 이동한다. 일반 이용 화면에는 웹 포털·키오스크 전환 링크나 관리 화면 링크를 두지 않는다. 휴대폰에서 OTP를 받은 이용자는 현장 단말을 방문해 수령한다.

- **웹 포털**: 습득자용 키오스크 위치 조회(지도), 분실자용 자연어 검색·5지선다 소유 확인·수령 OTP 발급
- **현장 키오스크**: 분실물 등록(정보 입력 → 촬영 2회 → 분석·보관함 개방 → 투입 완료), 분실물 수령(OTP 입력 → 보관함 개방 → 수령 완료)
- **장치 관리** (`/admin/devices`): 운영자가 별도 URL로 접속해 모든 키오스크의 알람·경고 현황을 보고, 키오스크를 선택해 장치 상태 확인과 경고 조치를 처리
- **단말 설정** (`/kiosk/settings`): 운영자가 별도 URL로 접속해 키오스크를 변경하거나 설정 초기화. 최초 미설정 상태에서는 `/kiosk`에서도 선택·확정을 제공

프론트 구현은 [백엔드 전체 기능 명세](../backend/docs/functional-spec.md)를 기준으로 진행한다. 화면별 등록·검색·소유 확인·사진 확인·수령 순서, 19개 API의 입력·응답·오류, 상태 전이와 인수 시나리오를 정리했다. 빠른 API 참조와 운영자 DB 확인은 [docs/api.md](../docs/api.md)를 따른다. 모든 업무 호출은 같은 출처의 상대 경로 `/api`로 보낸다.

키오스크 선택은 [FE-K01: 키오스크 최초 1회 설정](../docs/web-structure.md#fe-k01-키오스크-최초-1회-설정)에 따라 사용자가 최초 확정한다. `smart-lost-found.kiosk_id.v1`에 UUID 하나만 저장하고 전체 키오스크 목록으로 검증한 뒤 복원한다. 조회 실패 시 저장값을 유지하며, 저장소 접근 실패 시 안내 후 현재 화면의 메모리에서만 사용한다. 기기 인증을 제공하지 않는다.

## 로컬 개발

```bash
cd frontend
npm ci
npm run dev        # http://localhost:5173
```

백엔드에 CORS 설정이 없으므로 개발 서버는 `vite.config.js`의 프록시로 `/api/*`, `/docs`, `/health`, `/ready`, `/openapi.json` 요청을
EC2 백엔드(`http://52.78.12.168`)에 넘긴다. 로컬 백엔드를 쓸 때는 `SLF_API_TARGET=http://127.0.0.1:8000`을 개발 서버의 환경 변수로 설정한다.

## AI 비동기 연동 확인

- 분실물 검색은 `pending` 응답의 `attempt_id`로 조회를 반복하고, `retry_after_ms`만큼 기다린다. 진행 단계와 경과 시간을 표시하며 검색 재시작·화면 이동 시 이전 요청과 조회 타이머를 취소한다.
- 사진 분석은 `running` 동안 등록 정보를 `analysis_retry_after_ms` 간격으로 조회한다. 분석 성공 후에만 보관함 개방을 요청한다. 실패하면 사진 확인 화면에 오류를 표시하고 다시 시도할 수 있다. 재시도 시 서버 상태를 먼저 조회하므로 이미 실행 중인 분석이나 성공한 개방을 중복 요청하지 않는다.
- AI 상태 확인은 `/api/ai/status`의 작업 수와 최근 호출 통계를 표시한다. 설정 여부를 서비스 정상 여부로 해석하지 않으며, `p50`은 평균이 아닌 중앙값으로 표시한다.
- `npm test`는 모의 API 응답으로 지연·실패·시간 초과·재시도·취소 흐름을 검사한다. `npm run build`로 배포 빌드도 확인한다. Backend CI의 Docker 프론트 빌드 단계에서도 이 테스트를 실행한다. 실제 Gemini/Pi 연동은 별도 환경에서 확인해야 한다.

## 키오스크 경고와 Pi 연동 확인

- 키오스크 화면 진입 시각을 `since`로 고정하고 첫 조회부터 전달한다. 업무 화면 전환·키오스크 선택 변경에도 같은 값을 쓴다. 웹 포털 모드로 나가거나 페이지를 새로고침한 뒤 다시 진입하면 새 세션이다. 웹 관리자 화면은 기존처럼 과거 경고도 조회한다.
- 경고는 8초마다 `limit=200`으로 모든 페이지를 조회한다. 이미 본 페이지 뒤에 늦게 도착한 경고가 있을 수 있어 `reported_at`으로 기준을 전진시키거나, 이미 본 id만 있다는 이유로 조회를 중단하지 않는다. 조회 중에는 다음 폴링을 겹쳐 보내지 않는다.
- 화면에는 새로 수신한 warning을 우선해 최대 5건 표시한다. 수신 id와 표시 목록은 키오스크별로 유지하므로 확인한 warning이나 표시 한도에서 빠진 warning이 같은 세션에서 재등장하지 않는다. 사용자 확인은 화면에서만 숨기는 동작이며, 서버의 경고·보관·수령 상태를 변경하지 않는다. 서버에서 조치 완료된 동일 id의 warning은 다음 조회에서 숨긴다.
- `npm test`의 `kioskAlerts.test.js`는 고정 기준 시각, 중복·확인·표시 한도, 늦은 도착, 페이지네이션, 키오스크별 상태, 요청 취소·실패 복구를 모의 API로 검사한다.

실제 Pi 시험은 [시뮬레이터](../raspberry-pi/README.md#가상-센서와-mqtt)와 [설치·접속](../raspberry-pi/deploy/setup.md)을 따른다. 두 Pi의 연결, 백엔드의 실제 장치 모드(`DEV_FAKE_DEVICE=false`), 대상 키오스크와 테스트 칸을 먼저 확인한다. `DEV00000`은 실제 개방·완료 API를 호출하지 않으므로 실제 시험에는 정상 발급된 OTP를 쓴다.

1. 수정한 프론트로 키오스크 화면을 연다. Network에서 첫 `/api/alerts` 요청부터 `since`가 있는지 확인한다. 이후 경고가 들어와도 같은 값이어야 한다.
2. 보관함 Pi의 `raspberry-pi` 디렉터리에서 테스트 칸에 `python3 tools/sim.py locker N shock`을 보낸다. `PI_SIM_API_KEY`와 대상 Pi 주소는 설치 문서대로 설정한다. 새 `TAMPER`가 칸 번호와 함께 나타나면 확인 버튼으로 숨기고, 두 번 이상 폴링해도 다시 나타나지 않는지 본다.
3. 자동 모드에서 미수령을 재현하려면 해당 칸을 열기 전에 `python3 tools/sim.py locker N skip`을 실행한다. OTP로 열고 물건을 남긴 채 닫은 뒤, 개방 이후 센서 값이 서버에 반영된 것을 확인한다. 경고가 있어도 수령 완료를 누를 수 있고, 서버가 409 `ITEM_STILL_INSIDE`를 반환하면 안내와 다시 열기를 표시해야 한다.
4. 화면의 다시 열기로 같은 칸을 연다. 자동 모드면 물건이 제거되고, 수동 모드면 `python3 tools/sim.py locker N take`로 제거한다. 문을 닫고 수령 완료를 다시 눌러 성공하는지 확인한다. 요청 중에는 완료·재개방·처음으로가 비활성화되어야 한다.
5. 별도 수령 시험에서 처음으로를 눌러 키오스크 선택은 유지되고 입력만 초기화되는지 확인한다. 이 조작은 서버의 완료·취소가 아니다. 새 경고를 추가로 발생시켜 같은 문구라도 새 id이면 다시 표시되는지 확인한다.

warning 코드별 업무 화면 전환은 후속 범위다. 경고를 업무 완료 성공으로 간주하지 않는다. alarm은 아래 운영 중단 정책을 적용하며 모르는 code도 severity가 alarm이면 동일하게 중단한다.

## Alarm 운영 중단과 관리자 조치

- `/kiosk`와 `/kiosk/settings`는 `GET /api/kiosks/{id}/operation-status`를 즉시, 이후 2초마다 조회한다. 미해결 alarm은 과거 시각·대상 칸·5건 표시 제한과 관계없이 해당 키오스크 전체 업무를 막는다. 화면에는 닫기 버튼 없는 “관리자의 확인이 필요합니다!” 모달을 표시한다.
- 최초 운영 상태 확인 전이나 조회 실패 시에도 업무를 막고 자동 재조회한다. 새로고침·다른 탭의 설정 변경·ESC·배경 클릭으로 미해결 alarm을 해제하지 않는다. 서버도 업무 요청을 `423 KIOSK_ALARM_ACTIVE`로 거부한다.
- `/admin/devices`에서 관리자 로그인 → 첫 화면에서 키오스크 카드 선택 → 경고 검토 → 조치 내용 입력 → 문제 해결 및 운영 재개 가능 확인 → **조치 완료 및 운영 재개** 순서로 처리한다. 남은 alarm이 있으면 차단을 유지한다. 로그인 정보는 현재 화면 메모리에만 유지하므로 새로고침 후 재로그인한다. 서버의 단일 관리자 계정으로 기록하며 다중 관리자 계정 관리는 별도 범위다.
- 첫 화면은 등록된 모든 키오스크를 카드로 보여 준다. 카드마다 미조치 알람·경고 건수, 운영 중단 여부, 최근 경고 시각을 표시하고 위에 전체 합계를 둔다. 집계는 `GET /api/admin/kiosks/overview`를 먼저 호출하고, 아직 없는 백엔드에서는 `GET /api/alerts?unresolved_only=true&limit=200`으로 직접 센다. 200건을 채우면 일부만 집계했다고 알린다. 계약은 [프론트 요청](../docs/frontend-admin-overview-api.md)에 있다.
- 카드를 누르면 URL을 바꾸지 않고 같은 화면 안에서 상세 뷰로 바뀐다. 상세 뷰는 라즈베리파이 장치 연결과 보관함 센서 값을 각각 다른 표로 보여 주고, 그 아래에서 경고를 조치한다. 두 표를 나눈 이유는 장치 행에 문·무게·물건감지가 없고 보관함 행에 연결이 없어서, 한 표에 섞으면 빈 칸이 열과 어긋나기 때문이다. 보고된 값이 없는 항목은 '정상'이 아니라 '상태 모름'으로 표시한다.
- 이미 전송된 장치 명령은 결과를 기록하며, 중단·해결 조작으로 보관/수령 상태를 바꾸지 않는다. 모달 해제 후 현재 업무를 이어간다. `ITEM_MISSING` 사고 처리 결과나 폐기된 OTP는 복원하지 않는다.
- 백엔드에 `alembic upgrade head`(`0007_alert_resolution`)와 `ADMIN_USERNAME`/`ADMIN_PASSWORD` 설정이 필요하다. 실제 값을 저장소·VITE 변수에 넣지 않는다. 로컬 외에는 브라우저부터 백엔드까지 HTTPS 또는 보호된 전송 경로를 구성한다. 현재 공개 HTTP EC2 프록시에 관리자 비밀번호를 보내지 않는다.
- 기존 alarm도 미해결로 유지되므로 배포 전 과거 alarm을 검토한다. **새 프론트만 기존 EC2 백엔드에 연결하면 운영 상태 API가 없어 대기 안내가 나온다.** 백엔드·마이그레이션을 함께 반영한 환경에서 사용한다. 이번 로컬 검증은 EC2 배포나 실제 Pi 검증을 포함하지 않는다.
- API·인증·감사 기록 계약은 [F14 운영 중단과 관리자 조치](../backend/docs/functional-spec.md#f14-운영-중단과-관리자-조치)를 따른다.

## URL과 업무 중 이동

- `/web`, `/kiosk`, `/kiosk/settings`, `/admin/devices`는 직접 접속·새로고침을 지원한다. Vite와 기존 nginx의 SPA fallback을 사용하며 nginx는 변경하지 않았다. Vercel에도 해당 경로의 SPA rewrite를 추가했다. 백엔드 경로는 먼저 프록시 처리한다.
- 키오스크 입력 시작부터 완료까지 내부 이동과 브라우저 뒤로가기·앞으로가기를 `useBlocker`로 차단하고 현재 업무를 계속하도록 안내한다. 키오스크 변경·초기화는 별도 설정 화면에서만 제공하며, 미완료 업무가 있을 때 뒤로가기로 설정 화면에 진입할 수 없다. 다른 탭의 설정 변경은 업무가 끝난 후 반영한다.
- 설정 화면과 업무 화면은 같은 키오스크 상태를 공유한다. 내부 이동으로 경고 조회 기준 시각·수신 id 기억·저장소 사용 불가 시 임시 선택을 초기화하지 않는다. `/admin/devices`는 관리자 인증을 요구한다. `/kiosk/settings` URL은 별도 인증 기능이 아니며 운영 중단·업무 중 이동 가드를 적용한다.
- **처음으로**는 메인 화면으로 돌아간다. 서버에 등록·수령 건이 있으면 메모리에 보관하고 **진행 중인 업무 계속하기**를 표시한다. 오류 화면에서도 같은 키오스크를 유지하며 신규 업무를 시작하지 않는다. 첫 등록·개방 요청의 통신 오류·서버 오류로 결과가 불명확하면 관리자에게 상태 확인을 안내한다.
- 새로고침·주소창 이동·탭 닫기에는 업무 중에만 `beforeunload` 확인을 등록한다. 사용자가 이탈을 선택하거나 브라우저가 이벤트를 보내지 않으면 차단할 수 없다. 안내 문구도 브라우저가 정한다. [React Router의 이동 차단](https://reactrouter.com/how-to/navigation-blocking), [브라우저 이탈 확인의 제한](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event)을 따른다.
- **키오스크 설정만 복원하며, 강제 새로고침 후 진행 중이던 업무는 복원하지 않는다.** OTP·사진·등록/수령 ID를 브라우저 저장소에 남기지 않는다. 새로고침·오류 화면·처음으로는 서버 완료 또는 취소가 아니며, 복원만으로 장치·완료 API를 호출하지 않는다. 서버에 남은 업무의 복구·취소는 별도 운영 절차가 필요하다.

로컬 확인은 `/kiosk/settings` 직접 접속 → 키오스크 확정 → **키오스크 화면으로 돌아가기** → **분실물 수령** 순서로 진행한다. OTP 입력 화면에서 브라우저 뒤로가기를 누르면 설정 화면으로 이탈하지 않고 업무 유지 안내가 표시되어야 한다. 아직 개방 요청을 보내지 않았다면 **처음으로**로 돌아간 뒤 이동할 수 있다. 대기 화면 새로고침은 키오스크 선택을 복원해야 한다. `/web`에서는 위치 조회·소유 확인만 제공하고, `/admin/devices`에서는 센서 상태와 최근 경고를 확인한다.

브라우저 시험은 별도 포트 5189에서 모든 API를 모의 응답으로 처리한다. 테스트 서버의 프록시는 EC2에 연결하지 않는다. 실제 장치 동작과 배포된 Vercel의 rewrite는 별도 검증 대상이다.

## 배포

프론트엔드는 Vercel에 배포한다. 접속 주소: "https://smart-lost-found-nu.vercel.app/"

- `frontend/vercel.json`의 rewrite 규칙이 `/api/*` 요청을 EC2 백엔드(`http://52.78.12.168/api/*`)로 넘긴다. 브라우저는 Vercel 주소의 `/api`만 호출하므로 백엔드에 CORS 설정이 없어도 된다.
- 프론트 정적 파일은 Vercel이 제공한다. 이전에 설명하던 EC2 nginx의 `/` 서빙과 `deploy/Dockerfile`의 프론트 빌드 포함은 프론트 배포 경로에서 더 이상 쓰지 않는다. (deploy/ 문서는 별도로 확인이 필요하다.)
- `main` 병합 시 프론트엔드는 해당 상태로 자동 배포된다.
- 배포 주소가 HTTPS이므로 현재 위치(지도) 기능은 이 주소에서 사용할 수 있다.
- 로컬 개발은 기존과 같이 `npm run dev`를 쓴다. 개발 서버는 `/api`를 같은 방식으로 백엔드에 넘긴다.

## 현재 제한

- 질문 종료 시 후보가 하나 남으면 등록 사진을 보여 준다. 자동 등록에서 추출된 특징으로도 이 단계까지 진행할 수 있다. 사용자가 사진 속 물건을 본인 것으로 확인하면 수령 OTP를 발급한다. 후보가 여러 개 남으면 소유 확인 실패로 표시한다.
- 수령 OTP는 8자리(현재 백엔드는 Base32 A~Z·2~7)이며 영문 대문자·숫자를 받는다.
- 개발 서버(`npm run dev`)에서만 테스트 OTP `DEV00000`이 동작한다. 백엔드를 호출하지 않고 수령 화면 흐름만 보여 주며, 빌드본에서는 꺼진다.
- 현재 위치(지도)는 HTTPS 또는 localhost에서만 사용할 수 있다. HTTP 배포에서는 키오스크 목록만 보인다.
- 2차 촬영 각도 안내 문구(`SHOT2_GUIDE`)는 이미지 처리 AI 파트의 가이드가 나오면 바꾼다. 1차 촬영 완료 시 이 문구를 팝업으로 띄운다.
- 키오스크 등록은 물건 종류를 등록된 목록에서 고르는 방식이다(자유 입력 없음). 목록이 비어 있으면 종류 없이 바로 촬영 단계로 진행한다. 등록 요청의 `secondary_description`은 보내지 않는다.
- 화면은 터치 기준이다(결정 기록 0005: 키오스크 화면은 촬영 상자 옆 아이패드). 버튼·선택 항목은 최소 44px 터치 영역이고, 입력칸은 16px 이상이라 iOS에서 자동 확대되지 않는다. 스마트폰 웹에서도 같은 화면을 쓴다.
- 확인 화면(사진 2장)에서 "재촬영" 버튼으로 해당 촬영 단계로 돌아갈 수 있다. **다만 `docs/api.md`에 따르면 현재 백엔드는 같은 사진 번호의 저장 완료 요청을 반복하면 새로 찍지 않고 기존 저장 결과를 그대로 반환하며, 재촬영 자체를 아직 지원하지 않는다.** 즉 지금 상태로는 재촬영 버튼을 눌러 다시 촬영해도 백엔드가 이전 사진을 그대로 돌려줄 수 있다. 실제로 사진이 교체되게 하려면 백엔드에 재촬영(같은 `shot_order`의 덮어쓰기) 지원이 먼저 필요하다 — 백엔드 담당자와 협의가 필요하다.
- 촬영 중 카메라 자체 오류(전원 꺼짐 등)로 500이 내려오면 "현재 카메라에 기술적인 문제가 발생하였습니다. 관리자에게 문의하세요."를 안내한다. 처음으로 이동해도 기존 등록과 키오스크를 유지하고 같은 업무를 이어갈 수 있다.
