# 사진 여러 장으로 공통·특이 특징 탐색

이 문서의 자유 필드 실험은 고정 필드를 정하기 전에 사용한 당시의 프롬프트와 별도 출력 구조를 보존한다. 이후 현재 서비스 출력은 공통 필드 7개 + 특이 특징, 미확인 값은 null인 규격으로 변경했다.

## 현재 고정 필드로 다시 분석

```bash
cd imageprocess
conda activate gen_conda
python -m app.analyze_photos ../photos
```

`category`, `color`, `shape`, `surface_texture`, `brand`, `visible_text`, `structure`의 7개 공통 키와 `distinctive_features` 한 키를 사용한다. 브랜드와 인형 캐릭터는 모델의 시각 지식으로 자율 식별하도록 허용하고, 캐릭터명은 외형 근거와 함께 특이 특징에 담도록 요청한다. 정답 이름을 입력하지 않는다. 판단 불가 값은 null이다.

새 결과는 `outputs/fixed_features/run-*/`에 저장한다. 이 명령은 실제 Gemini API를 호출한다. 실행·출력 안내는 [실행 안내](usage.md)의 사진 폴더 전체 분석에 있다. 아래 `app.explore_features` 명령은 이전의 자유 필드 탐색 조건을 재현할 때만 사용한다.

## 입력과 추출 기준

- 입력: 사진 한 장과 파일명에서 얻은 카테고리. 추가 물품 설명이나 정답 특징은 제공하지 않는다.
- `wallet1.jpg`, `wallet2.jpg`의 숫자는 제거하여 둘 다 `wallet`로 전달한다.
- `doll`은 `plush_toy`, `pencilcase`는 `pencil_case`, `airpod`는 `wireless_earbuds`로 해석한다. 파일명에 들어 있는 상품명만으로 브랜드를 정답처럼 주지 않는다.
- 사진은 기존 전처리를 거쳐 긴 변 최대 1280px로 축소된다. 실제 사용 설정과 입력 사진 해시는 결과에 기록한다. 원본 파일은 수정하지 않는다.
- 공통 특징: 여러 물품에서 재사용할 수 있는 속성 개념을 모델이 직접 선택한다. 이름이나 값의 목록은 미리 지정하지 않는다. 5~7개를 목표로 하되 관찰 근거가 부족하면 더 적게 허용한다.
- 특이 특징: 유사한 물품과 구분하는 데 도움이 될 만한 구체적 관찰을 최대 7개 추출한다. 모든 항목에 관찰 근거와 구별에 도움이 되는 이유를 요청한다.
- 값·근거·이유는 한국어, 필드 이름은 영어 snake_case를 요청한다. 글자와 브랜드 표기는 읽히는 원문을 유지한다.
- 각 사진은 독립 요청이다. 다른 사진을 비교해서 유일성이나 소유권을 판단하지 않는다.
- 모델이 쓴 근거도 검토 대상이다. JSON 검증은 사실성 검증을 대신하지 않는다.

## 실행

`imageprocess/.env`의 기존 Gemini API 키와 모델 설정을 사용한다. 이 명령은 실제 사진을 Gemini API에 전송하여 추론한다.

```bash
cd imageprocess
conda activate gen_conda
python -m app.explore_features ../photos
```

`--model`로 모델을 바꿀 수 있다. 이번 실험은 설명이 많은 별도 출력이므로 출력 예산 기본값은 8192 tokens이며, `--max-output-tokens`로 조정한다. temperature는 0이다. 예산은 실제 사용량이 아니며 실제 토큰 수는 개별 JSON의 `usage`에서 확인한다.

호출은 순차 실행하고 자동으로 재시도하지 않는다. 키·모델·할당량·네트워크 문제처럼 공통 API 오류가 발생하면 추가 요청을 중단하고 처리한 결과까지 남긴다. 다시 실행하면 새 폴더에서 처음부터 진행하므로 재호출이 발생한다.

## 결과

매 실행은 `outputs/feature_exploration/run-*/`에 별도로 저장된다.

| 파일 | 내용 |
|---|---|
| `report.md` | 사진별 공통·특이 특징, 근거, 불확실성, 추론 시간과 필드 출현 빈도 |
| `01_*.json` 등 | 사진별 입력 카테고리, 구조화된 결과, 경고, 토큰 사용량, 사진 해시 |
| `field_inventory.json` | 필드별로 공통/특이로 선택된 사진 수와 실제 값 |
| `prompt.txt` | 카테고리 힌트를 제외한 공통 프롬프트 원문 |
| `response_schema.json` | 실험용 응답 구조. 특징 이름은 열거형으로 제한하지 않음 |
| `manifest.json` | 모델·설정·입력 목록·실행 시각·성공 여부 |

빈도 집계는 동일한 이름만 합친다. 동의어 필드를 임의로 합치지 않으므로 모델의 이름 선택이 얼마나 일관적인지도 확인할 수 있다. 공통으로 분류된 사진 수가 많다는 사실만으로 해당 필드를 서비스의 필수 필드로 확정하지 않는다.

스키마를 정할 때는 반복해서 등장하는 공통 개념, 물품 종류에 따른 누락, 관찰 정확도, 특이 특징과 중복되는 정도를 함께 검토한다. 사진이나 원시 결과를 팀 저장소에 커밋하지 않는다.
