# 0004. 보관함은 만들지 않고, 가상 센서로 이상 상황을 시뮬레이션한다

- 날짜: 2026-11-18
- 상태: 결정 (2026-11-18 팀 회의, 교수님 조언)

## 배경

[결정 기록 0002](0002-locker-led-button.md)에서 잠금장치 대신 LED와 버튼을 쓰기로 했고, [결정 기록 0003](0003-mqtt-device-status.md)에서 물건 유무와 장치 상태를 MQTT로 알리자고 제안했다. 센서를 실제로 쓰려면 센서를 사고 보관함 상자도 만들어야 하는데, 비용과 제작 모두 부담이었다.

그래서 11/18 회의에서 팀원들과 상의하고, 교수님께 가상의 센서가 있다고 가정하고 특정 상황을 시뮬레이션해 서비스가 어떻게 대응하는지 구현하고 시연해도 되는지 여쭤보았다. 가능하다는 답을 받았다.

## 결정

- 보관함을 하드웨어로 직접 만드는 대신 MQTT와 가상 센서를 쓴다. 실물 제작보다 실제 서비스의 기능, 즉 이상 상황을 알아채고 알리는 것에 집중한다.
- 보관함 상자는 만들지 않는다. 보관함 Pi의 LED와 버튼(0002)은 열린 칸 표시와 문 닫힘에 그대로 쓴다.
- 센서는 실물 대신 가상으로 둔다. 실제로 단다면 쓸 부품을 정하고, 그 부품이 읽었을 값을 시연용 명령으로 만든다.
- 팀 회의에서 시뮬레이션하기로 한 상황은 세 가지다.
  1. 누군가 보관함 문을 강제로 열려고 하면 경보를 울린다.
  2. 보관하라고 열어 준 칸에 물건이 들어오지 않았거나, 수령하러 온 사람이 문을 열고 닫았는데 물건이 남아 있으면 알린다.
  3. 촬영이 끝났는데 촬영 상자에 물건이 남아 있으면 알린다.
- 상황 판단은 Pi(엣지)에서 하고, 결과를 MQTT로 보낸다. 촬영과 개방 같은 명령은 지금처럼 HTTP로 둔다(0003).
- 나눠서 맡는다. Pi의 가상 센서·판단·MQTT 발행·시연 도구는 라즈베리파이 담당, 브로커와 백엔드 구독은 백엔드 담당이 맡는다. 화면에 띄울 내용은 프론트 담당과 정한다.

## 가상 센서

| 위치 | 실제로 단다면 | 고른 이유 | 가상으로 만드는 값 |
| --- | --- | --- | --- |
| 보관함 문 | 자석식 문 센서(리드 스위치) | 문이 열렸는지 직접 알 수 있고 값이 싸다 | 문 열림·닫힘 |
| 보관함 문 | 진동(충격) 센서, 예: SW-420 | 문이 열리기 전에 억지로 열려는 충격을 먼저 알 수 있다 | 약한·강한 충격 |
| 보관함 바닥 | 무게 센서(로드셀과 HX711) | 압력 센서(FSR)는 Pi에 아날로그 입력이 없어 변환 칩이 따로 필요하고 가벼운 물건을 놓친다. 로드셀은 무게를 g 단위로 읽는다 | 무게(g) |
| 촬영 상자 바닥 | 무게 센서(로드셀과 HX711) | 같은 이유 | 무게(g) |

## 상황 판단

| 경고 | 등급 | 언제 |
| --- | --- | --- |
| `FORCED_OPEN` 강제 개방 | 경보 | 개방 명령 없이 문이 열렸다. LED가 빠르게 깜빡인다 |
| `ITEM_MISSING` 도난 의심 | 경보 | 강제로 열린 칸이 닫힐 때 물건이 사라졌다 |
| `TAMPER` 개방 시도 | 경고 | 닫힌 칸에 강한 충격이 왔다 |
| `ITEM_NOT_DEPOSITED` 보관 안 됨 | 경고 | 빈 칸을 개방 명령으로 열었다 닫았는데 그대로 비어 있다 |
| `ITEM_NOT_TAKEN` 수령 안 됨 | 경고 | 물건이 있던 칸을 개방 명령으로 열었다 닫았는데 그대로 있다 |
| `CAPTURE_ITEM_LEFT` 촬영 상자에 남음 | 경고 | 마지막 촬영 뒤 정해진 시간(기본 120초)이 지나도 촬영 상자에 물건이 있다 |

- 보관과 수령은 문이 열릴 때의 무게로 구분한다. 빈 칸을 여는 것은 보관이고, 물건이 있는 칸을 여는 것은 수령이다. 백엔드는 배정 기록과 맞춰 한 번 더 확인할 수 있다.
- 무게는 문이 닫히고 1초 뒤에 읽는다. 문이 닫힐 때 흔들린 값이 가라앉기를 기다리는 것이다. 10g보다 무거우면 물건이 있다고 본다.
- 촬영 상자는 촬영할 때마다 시간을 다시 잰다. 물건을 돌려 두 번째 사진을 찍는 동안에는 경고하지 않는다.

## 지키는 것

- 센서 값만으로 보관이나 수령을 완료하지 않는다(백엔드 결정 D03·D06). 센서는 알림과 화면 표시에만 쓴다.
- 백엔드와의 HTTP 통신 규약은 바뀌지 않는다. 시연용 경로(`/sim`)는 `PI_SIMULATION=true`일 때만 열리고 같은 API 키로 보호한다.

## 영향

- Pi에 MQTT 라이브러리(paho-mqtt)가 필요하다.
- 브로커, 백엔드 구독, 화면 표시가 필요하다. 토픽과 메시지 형식은 [MQTT 규약](../../../docs/mqtt-protocol.md)에 있다.
- 가상 무게는 파일에 저장해서, Pi를 다시 켜도 보관 중인 칸의 무게가 남는다.
