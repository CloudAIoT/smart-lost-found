# 실험 0003. 키오스크 화면 확인과 실제 Pi 등록 시험

- 날짜: 2026-11-25
- 장비: 촬영 Pi와 보관함 Pi(Raspberry Pi 4), 보관함 칸별 LED·버튼, EC2의 백엔드와 MQTT 브로커(Tailscale 안), 키오스크 웹
- 키오스크: `00000000-0000-0000-0000-000000000001`(Swagger 테스트 키오스크)
- 코드: main `f093e22`. 키오스크의 경고 표시·다시 열기(#63)와 사진 분석 진행 표시(#62)가 들어 있다

## 왜 했나

프론트 담당이 키오스크에 경고 표시와 다시 열기를 넣고(#63), 실제 보관함이 열리는지와 경고가 화면에 어떻게 보이는지 확인해 달라고 했다(#64). 수업 시간에 실제 Pi를 켜기 전에 화면부터 따로 확인하고, 수업에서는 두 Pi를 켜서 등록 흐름을 시험했다.

## 방법

- 화면 확인(오전): main을 빌드해 맥의 브라우저에 띄우고, 백엔드와 Pi의 응답을 흉내 내서 화면 동작만 보았다. 빌드한 파일은 운영 사이트의 파일과 같았다. 실제 Pi 시험이 아니다.
- 수업 시험(16시 17분~39분): 두 Pi를 휴대폰 핫스팟에 붙이고, Pi 서비스 로그와 서버의 장치 상태·경고 API를 같이 보았다.

### 수령 완료 버튼이 안 켜지는 이유

화면은 장치 상태에서 '열림'을 본 다음 '닫힘'을 봐야 버튼을 켠다. 그런데 Pi는 개방 명령을 받자마자 '열림'을 보내서, 서버에 저장된 시각이 화면이 기억한 '연 시각'보다 빠르다. 화면은 '연 시각'보다 먼저 저장된 상태를 무시하므로 '열림'을 못 본 것이 된다.

| 조건 | 버튼 |
| --- | --- |
| 화면과 서버 시계가 같고 12초 뒤 닫음 | 안 켜짐(24초 기다림) |
| 화면 시계가 2초 빠르고 12초 뒤 닫음 | 안 켜짐 |
| 화면 시계가 2초 느리고 12초 뒤 닫음 | 켜짐 |
| 화면 시계가 2초 느리고 2초 뒤 닫음 | 안 켜짐 |
| 가짜 Pi 모드(칸 상태가 들어오지 않음) | 안 켜짐 |

버튼이 안 켜지면 '처음으로'도 막혀 있어서 새로고침해야 나갈 수 있다. 고치기 전까지는 다음처럼 하면 켜진다(화면 확인에서만 해 봄).

- OTP를 넣기 전에 `locker N skip`, 열리고 3초쯤 뒤 `locker N take`, 10초 넘게 열어 두었다가 닫는다. 무게가 바뀔 때 '열림' 상태가 다시 나가기 때문이다.
- 이미 멈췄으면 `locker N force-open`으로 열고 10초 넘게 두었다가 닫는다. 강제 개방 경보가 한 번 남는다.

### 찾은 문제와 처리

1. 무게가 저절로 들어가지 않음: 보관함 Pi에 자동 모드(#59) 이전 코드가 돌고 있었다. 코드를 올려 해결했다([문제 해결 기록 5](../troubleshooting.md)).
2. 촬영한 사진에 물건이 다 담기지 않음: 설정으로는 더 넓게 찍을 수 없어 카메라 높이를 조절해야 한다([문제 해결 기록 6](../troubleshooting.md)).
3. 촬영 Pi가 두 번 꺼짐: 원인을 아직 모른다. 다시 켠 뒤 전압 부족 기록은 없었고(`throttled=0x0`), 꺼지기 전 로그는 남아 있지 않았다. 전원선과 어댑터를 확인해야 한다.

## 결론

- 등록 흐름에서 백엔드의 개방 명령으로 실제 칸이 열리고(LED 깜빡임), '보관 안 됨' 경고가 서버에 저장되고, 다시 열기 뒤 보관 완료까지 가는 것을 확인했다.
- 자동 모드는 보관함 Pi에 켜졌지만, 실제로 칸이 열려 무게가 바뀌는 것은 아직 보지 못했다.
- OTP 수령과 나머지 경고 5가지(FORCED_OPEN, TAMPER, ITEM_MISSING, ITEM_NOT_TAKEN, CAPTURE_ITEM_LEFT)가 화면에 뜨는 것은 이번에 실제 Pi로 시험하지 못했다.

## 남은 일

- 자동 모드로 보관·수령 한 바퀴, OTP 수령, 나머지 경고를 실제 Pi로 시험하고 화면 사진을 남긴다.
- 촬영 Pi의 코드를 올리고, 카메라 높이를 조절해 다시 찍고, 전원을 확인한다.
- 화면에서 고칠 것은 [프론트 요청 문서의 확인 결과](../../../docs/frontend-device-alerts.md#확인-결과-2026-11-25)에 적었다.
- GitHub production 변수 `DEV_FAKE_DEVICE`가 `true`이다(11/25 16:36 기준). main에 병합되어 EC2가 다시 배포되면 가짜 Pi 모드로 돌아가므로, 실제 Pi로 시험하기 전에 백엔드 담당과 맞춘다.
